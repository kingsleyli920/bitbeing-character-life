# 评测记录（EVALUATION）

本文件记录**实际运行**得到的结果。没有运行过的项写“未运行”。fixture（确定性假模型）的结果只证明工程流程，不代表 AI 生成的质量。

- 真实模型：OpenRouter `anthropic/claude-haiku-5.5`，`reasoning.effort = low`。
- **最终流程**：`chapter-v6` + `consistency-v3`（101 段长测）。多角色、走向、注入三个场景是用 `chapter-v5` + `consistency-v2` 跑的：v6 只改了长篇才会触发的生活面轮换和检查器读取的摘要范围（8 段以内两者相同），预算也不够把所有场景再跑一遍，所以没有重跑。
- 质量结论由我逐段阅读得出，并引用具体段落；没有使用模型给自己打分。为了在版本之间做公平对比，另外写了一个**独立审计**（`npm run eval:audit`）：用一套与生成无关的 prompt，把每一段和此前全部摘要对照找矛盾，并独立判断每段的主线生活面。审计也是同一个模型，只作为辅助证据，引用的矛盾我逐条读过。
- 原始数据：`eval/out/<场景>/`（数据库、全文、服务日志，不入库，可以用 `npm run eval -- <场景>` 复现）。代表性全文和报告复制在 [docs/eval/](eval/)，三版长测的审计结果在 [docs/eval/audit/](eval/audit/)。

## 1. 选型与早期冒烟

### 1.1 模型选型探针（2026-10-24，花费 $0.02）

相同 prompt（周野，写约 900 字的第 1 段，要求 JSON schema 输出）：

| 模型 | JSON 有效 | 耗时 | 费用 | 观察 |
|---|---|---|---|---|
| Claude Haiku 5.5 | ✅ | 21s | $0.0012 | 字数符合要求；记忆提取最好（人物、承诺、线索都写出名字和原因） |
| DeepSeek V4 Pro | ✅ | 30s | $0.0007 | 文笔丰满，但写了 1694 字，超出要求；记忆条目笼统 |
| Kimi K2.6 | ❌ | 44s | $0.0165 | 没有遵守 schema，字段名是自创的；推理 token 多 |
| Qwen3.8-flash | ❌ | 92s | $0.0029 | 6000 个 token 全花在推理上，正文被截断 |
| GLM-5.3 | ✅ | 6s | $0.0002 | 正文只有 58 字 |

结论：选 Haiku 5.5；请求加上 `provider.require_parameters: true`，服务端必须二次校验。

### 1.2 第一次 3 段冒烟（M3，`chapter-v1`）

3 段全部一次成功，每段约 $0.0019、15–26 秒。阅读发现：3 段只覆盖了大约 12 小时；“父亲发消息催款”每段都出现一次，剧情原地打转。据此把 prompt 升级到 `chapter-v2`：每段至少发生一件不可逆的事；相邻两段不重复同一个动作或道具；时间可以跳过几天。

### 1.3 改动前的一轮多角色评测（`chapter-v2`，没有补全设定）

5 个角色各 8 段 + 走向分支，共 66 段，全部完成，费用 $0.21。出现 16 次不合格输出，**全部**是“摘要超过 240 字”。把这 16 次的原始输出用新的软长度规则（超长截断并记 warning）重新校验，16 次全部可以通过。修复之后，v2、v3、v4 的正式评测里，章节生成没有再出现因为摘要长度导致的不合格。这一轮的数据保留在 `eval/out/*-pre-profile/`。

## 3. 走向可控性（direction，v5）

**方法**：同一角色先写 4 段共同历史，然后把数据库复制 3 份（三份的段落、记忆、状态完全相同），每份设置不同的走向，再各写 3 段（第 5–7 段）。走向使用作业文档里的示例。26 段全部成功，4 个走向分支的 12 段全部写明了如何落实走向。全文见 [docs/eval/direction/](eval/direction/)。

### 3.1 陈一帆（众筹页的护眼说法和色温数据有问题）

| 分支 | 第 5–7 段 |
|---|---|
| 无走向 | 公开承认部分批次偏暖，标出超标批次 → 连续加班胃痛，三百八十六元药费用掉了给家里买冰箱的钱 → 复查时遇到湘语老乡护士，第一次对外人说起冰箱的承诺 |
| **更悲惨一点** | 包装要重印、发货推迟 → 预售停滞，她公开承认包装印错、承诺按批次退差价 → 一夜一百四十多条退款申请，资金不够只能先退一批，预售暂停，转正被重新评估；晚上她仍发了一条轻快的动态，母亲在评论区夸她 |
| **更多的感情故事** | 巷口买粥偶遇同事阿杰，他坦白刚分手，她说出“在你面前不想演” → 他兑现“先给你看结果”的约定，两人在样品盒前说出各自的担心 → 末班车上她第一次向他坦白家里不知道的真实处境，他送她到楼下。没有表白 |

### 3.2 阿秀婆（台风后，开发商在收东边的老宅）

| 分支 | 第 5–7 段 |
|---|---|
| 无走向 | 陪孙子找已动摇的邻居陈伯 → 孙子第一次以本地人身份去村委会查规划图，查到老宅是保留区 → 孙子劝陈伯，陈伯答应周三前给准话 |
| **故事更有冒险性一点** | 祖孙探访贴了“待拆”的老巷 → 清晨潜进旧仓库找到报价表，“海屋”旁写着“待定，可加”，笔迹是她儿子的 → 跟踪开发商到码头，偷拍到交接，认出是儿子的合伙人 |
| **故事更有哲理一点** | 邻居已签意向书，她摸着墙上两家人修屋顶留下的刻痕，说“守的是在这里生活过的日子” → 和孙子一起拓印门楣上的堂号，纸破了一道口，“字还在，破的地方也记下” → 老渔民把阿公用过的旧麻绳交给孙子，讲打活结的道理 |

### 3.3 结论

- 三个分支在同一位置分叉，后续的**事件**完全不同：“更悲惨”是退款、暂停预售、前途受损的连锁后果；“感情”是一个具体的人和三次具体的对话；冒险分支是潜入、跟踪、偷拍；哲理分支是拓印、旧麻绳和选择。不是只换了形容词。
- 走向是循序推进的：“更悲惨”逐段升级，“感情”三段都没有越过“表白”这一步。
- 人物没有变形：各分支里陈一帆都坚持不在宣传里说假话，阿秀婆都嘴硬心软。
- 共同历史会限制分支：阿秀婆的三个分支都围绕“开发商收房”，走向改变的是处理方式和气质。
- v2、v4 的同一场景结论相同（报告存档在 `docs/eval/reports/`）。

### 4.2 时间（v4 → v5 解决）

- v4 让模型自己报“过了几天”，结果每次只跳 1–3 天，101 段只覆盖 98 天；星期还常对不上（例如第 21 天写周五、3 天后写周二）。
- v5 起日期由服务端掌握：v5 跨度 298 天、v6 275 天，都是一年中的大半；季节、节日跟着走（v6：梅雨 → 中秋 → 一月初下雪、林晚发烧转成肺炎 → 春节后母亲来上海住下）；审计的星期断链为 0。
- 不足：跳跃偏机械，大多是“14 天”这一档（日历对照表里的选项），读起来像每隔几段固定跳两周。

### 4.3 题材（v5 部分解决，v6 明显改善，仍有不足）

| | v4 | v5 | v6 |
|---|---|---|---|
| 审计分类：主线“旧事秘密” | 70% | 65% | **47%** |
| 审计分类：其他主线 | 家人 15、钱 8、工作 6、感情 2 | 家人 13、钱 11、感情 7 … | 钱 16、家人 13、身体 12、工作 6、居所日常 5 … |
| 模型给自己标的“旧事秘密” | — | 27% | 14% |
| 检查器判断的“旧事秘密” | — | — | 38% |

- v5 的教训：模型给自己标的生活面很乐观（自标 27%，审计 65%），用自评驱动轮换没有用。v6 改用检查器的判断，并在“要求换主线却没换”时重写（8 次）。
- 读起来的变化（v6）：母亲的高血压成了一条贯穿的生活线——停药、复查、改医嘱、带着血压计来上海住下（第 22–30、92–98 段）；房租分期、当铺赎表、卖相机凑钱（第 6、16、38、82 段）；接电台的写稿合同并坚持删掉使用历史录音的条款（第 66–72 段）；自己得肺炎（第 80–83 段）。
- 仍然存在：每揭开一层旧事，模型很快又引入新的“神秘人声/旧线路”（第 89 段座机里的女声、第 96 段收音机里的女声）；“旧事秘密”仍是占比最大的一类。

### 4.4 一致性（v5 起有检查，减少了，没有消除）

- 审计的明确矛盾：v4 21 处 → v5 14 处 → v6 12 处（11 段）。
- v6 剩下的矛盾多半是**钱和物品的账**：第 32 段母亲说八月房租取自存折，而第 18 段林晚是卖旧物凑的；第 56 段又写八月房租“待缴”，而第 31 段已经付清；第 89 段一月下旬写“梅雨季比去年还黏人”；第 99 段挂号条在谁手里前后不一。检查器在写作时漏掉了这些。
- 检查器的拦截是有效的：v6 运行中拦下并重写了 29 次明确矛盾，我抽读的拦截都是真问题，例如 v5 第一次长测里，第 5 段初稿把已经来过的男孩写成第一次上门。第一版检查器有误报（把剧情揭晓判成矛盾），修正后重跑了全部评测（§7）。
- 代价：每段多一次调用，约多 $0.001–0.002、5–10 秒；约三成的段落经过重写。

### 4.5 记忆、走向和人物（v6，读全文得出）

- **记忆**：邻居老葛出现在 66 段（第 1–101 段都有），帮工小满 52 段，母亲 58 段，前男友陆川 19 段。第 7 段母亲第一次来时说“你爸当年也是这句话”，第 30 段她讲出父亲修红灯牌烫伤手的往事，第 50 段又提起，前后一致。
- **线索收尾**：第 1 段的磁带在第 8–9 段揭晓（被吞掉的字是“回”）；红灯牌的改焊者从第 13 段查起，第 53–58 段揭晓是父亲的工友周明远，第 72 段确认父亲为替他隐瞒被记大过；第 74 段新引出的夜班公交收音机，在第 86 段找到改焊的金师傅。卷摘要 10 卷里 7 卷仍以“仍未…”收尾。

## 6. 迭代历程（每一版为什么改）

| 版本 | 发现的问题（怎么发现的） | 改了什么 | 效果 |
|---|---|---|---|
| v1 → v2 | 3 段只过了 12 小时，“父亲催款”每段都出现（冒烟阅读） | 每段至少一件不可逆的事；相邻两段不重复同一个动作 | 原地打转消失 |
| v2 → v3 | 一个谜团拖了 80 段，10 卷摘要都写“仍未确认”（读 101 段） | 线索老化、线索上限、题材轮换 | 收束率 0.27 → 0.90 |
| v3 → v4 | 101 段只过了 42 天（读 101 段） | 模型报告过了几天，太慢就要求跳 | 42 → 98 天 |
| v4 → v5 | 时间每次只跳 1–3 天、星期对不上；70% 在追旧事；21 处矛盾；摘要混英文（阅读 + 审计） | 服务端日历；生活面标注与轮换；提交前一致性检查；重试时告诉模型原因；短字段英文校验 | 跨度 298 天、星期错误 0；矛盾 14；题材几乎没变（65%） |
| v5 → v6 | 模型自评的生活面不可信；检查器漏掉指向很早段落的矛盾（审计对比） | 轮换以检查器的判断为准，没换就重写；检查器看全部摘要 | 题材 47%；矛盾 12 |

## 7. 开发中发现并修复的问题

| 问题 | 怎么发现的 | 原因 | 修复与证据 |
|---|---|---|---|
| 生成途中设置新走向，下一段 prompt 里的“已生效段数”多算 1 | L1b 测试失败 | 生效起点用了“当前段数 + 1”，没有考虑进行中的任务 | 有进行中任务时取它的目标段 + 1；测试断言 |
| 双击「继续」后再点一次没有反应，新段落也不刷新 | 用浏览器亲自操作 + 对照服务端请求日志 | 每次点击前调用 `mutation.reset()`，双击的第二次 reset 清掉了进行中请求的回调，锁永远不释放 | 回调移到 `useMutation` 上；新增回归测试；**反向验证**：旧实现跑同一用例会失败 |
| jsdom 中双击仍可能发出 2 次 POST | L1d 测试失败，加日志定位 | 请求完成和按钮重新渲染为禁用之间有一个异步窗口 | 先把任务写入缓存再释放锁；`start()` 同步检查缓存 |
| 摘要超长导致整段作废（一章连续 3 次） | 真实评测 | 摘要长度属于软问题，却按硬错误处理 | 软长度截断并记 warning；16 次历史失败回放后全部通过 |
| 删除角色后费用记录被级联删除，费用上限可以被绕过 | 设计 schema v2 时审查发现 | `model_calls` 通过外键跟随任务级联删除 | v2 迁移去掉级联；测试断言删除前后累计费用不变 |
| 工作台不显示「删除导入的角色」 | L1d 测试失败 | 用 `getQueryData` 一次性读取角色列表，没有订阅变化 | 改用 `useCharacters()` 订阅 |
| 删除角色后首页又跳回这个已删除的角色（404） | L5 测试的控制台报错检查 | 首页用了缓存里的旧列表，且“上次打开的角色”就是它 | 首页等列表重新拉取完成；删除时清掉记录 |
| 视觉基线截图位置不稳定 | 人工检查基线 | 新段落到达后的平滑滚动是异步的 | 尊重“减少动态效果”；测试中等待滚动完成 |
| 第一版界面和作业参考交互不一致（书架 + 阅读器） | 负责人对照文档指出 | 没有仔细对照参考图 | 改成参考图的单页两栏工作台，并按参考图的 [推理] 标注加入角色卡补全 |
| 卷摘要超长被判失败（v2 长测 4 次） | 真实长测 | 卷摘要没有软长度规则 | 截断到 300 字；v3、v4 都是 10/10 |
| **长篇停滞**：一个谜团拖了 80 段，10 卷摘要全部“仍未确认” | 通读 v2 的 101 段 | 防遗忘规则只要求“记得”，没有任何规则要求“收尾” | v3：线索老化、线索上限、题材轮换；收束率 0.27 → 0.90（§4） |
| **故事时间几乎不动**：101 段只过了 42 天 | 通读 v3 的 101 段 | 时间推进只是软要求，而且无法测量 | v4：每段报告 `daysSincePrevious`，最近 5 段不足 3 天时要求跳时间；42 天 → 98 天（§4） |
| **时间只跳 1–3 天、星期对不上** | 通读 v4 的 101 段 + 审计脚本的“星期断链”统计（7 处） | 模型自己数日子、自己算星期 | v5：日期由服务端掌握，模型只报 `storyDate`，日期倒流和星期不符直接判不合格；上下文给出日期对照。星期断链 7 → 0，跨度 98 → 298 天（§4） |
| **前后矛盾**（母亲把丈夫叫“我哥”、欠钱方向写反、已经留下的包又出现在旅馆） | v4 101 段的独立审计：21 处 | 只靠写作 prompt 里的“不要矛盾”挡不住 | v5：提交前一致性检查，矛盾必须原样引用正文，查到就带原文重写（§2.7、§4） |
| 摘要里混入英文词 “answer” | 阅读 v4 摘要（5 段） | 没有语言校验 | v5：短字段出现正文和上下文都没用过的英文词判不合格；v5/v6 长测各拦下 1–2 次（§4.4） |
| 第一版检查器把剧情揭晓（“原来那台收音机不是父亲的”）判成矛盾，还为“便条压在账本下面”这类小出入触发重写 | v5 长测前 17 段的拦截记录，逐条阅读 | 判定口径没有区分“揭晓”和“笔误”、“影响情节”和“小出入” | `consistency-v2`：揭晓不算矛盾，小出入记 soft；停掉跑了一半的评测，全部重跑 |
| **模型给自己标的生活面不可信** | v5 长测：模型自标“旧事秘密”27%，独立审计 65% | 轮换规则读的是模型的自评 | v6：一致性检查器顺带判断主线生活面，轮换以它为准；要求换主线却没换就重写。审计 65% → 47%（§4） |
| 检查器漏掉指向几十段之前的矛盾 | 对比审计结果：v5 漏掉的矛盾多半出自很早的段落 | 检查器只看最近 15 段摘要 | v6：检查器看全部段落摘要（每段多约 $0.0012） |
| 10 次一致性检查因输出达到 2000 token 上限被截断（v6 长测） | 评测后统计 `model_calls` | 看全部摘要后推理变长 | 这 10 段按设计跳过检查直接保存并记警告；之后把上限调到 4000（评测是用 2000 跑的） |
| 评测数据库 schema 版本不同，演示库合并失败 | 重建 `demo/demo.db` | 合并脚本用 `SELECT *` | 按源表实际列名复制 |
