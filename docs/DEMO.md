# 演示脚本（3–5 分钟）

## 准备（演示前 5 分钟）

```sh
nvm use 24 && npm ci
npm run demo                 # 用仓库里的演示数据库启动：已有 5 个角色的多章故事和 1 个 101 章故事
# 浏览器打开 http://127.0.0.1:5210 ，窗口宽度约 1280
```

- `npm run demo` 会先把 `demo/demo.db` 复制到 `data/demo.db` 再启动，所以演示时的操作不会改动仓库里的文件；`npm run demo -- --reset` 可以恢复成初始数据。
- 演示库里的故事都是最终版本（v4）评测时真实生成的：5 个角色各 8 段、林晚 101 段、导入角色「顾青」2 段（注入测试）。页面右上角的“已用 $0.42”是这些故事生成时的实际花费。
- 现场需要生成新段落时，`.env.local` 里要有 `OPENROUTER_API_KEY`。没有网络时，改用 `npm run dev:fixture` 演示流程（页面会显示「Fixture 模式」）。
- 一段大约需要 15–30 秒，可以利用等待时间讲解。

## 流程

| 时间 | 操作 | 要讲的点 |
|---|---|---|
| 0:00–0:30 | 打开首页：左「角色卡信息」，右「角色生活故事」（和作业参考图一致） | 5 个原创角色：年龄、城市、职业、目标、叙述形式（小说 / 日记 / 社交动态）都不同；左栏逐条列出设定，[推理]/[想象] 是 AI 补全的字段，悬停可看依据 |
| 0:30–1:15 | 用左栏的角色按钮依次切到 周野 → 宋知微 → 陈一帆，看各自的「生活故事序列 1」 | 同一套系统，三种完全不同的声音：四川话第一人称、物理老师的日记（日期 + 天气 + 物理比喻）、正文里穿插「动态」卡片 |
| 1:15–2:15 | 切到周野 → 右上角「故事走向」→ 点示例「更悲惨一点」→ 保存 →「点击继续生成」 | 走向从下一段生效，已有段落不变；等待时展开左栏「记忆」：未解决的线索、人物，每条都标了来源段落，点「第 N 段」可以跳回原文 |
| 2:15–2:45 | 新段落出现 → 展开底部「本段走向」 | 模型说明了通过什么行动、冲突、后果来推进走向；走向改变的是事件，不只是形容词 |
| 2:45–3:15 | 刷新页面 | 章节、走向、记忆都还在；生成中刷新也不会重复提交（可以讲 requestId 与 409 的机制） |
| 3:15–4:15 | 切到林晚（101 段）→「更多 → 目录」→ 跳到第 1 段 → 再跳到第 101 段 → 打开「记忆 / 卷摘要」 | 长故事证据：第 1 段埋下的人和事在第 90 段以后还会被提起；10 段卷摘要；第 25 / 50 段的走向变化；第 60 段生成中强杀服务后，从中断处继续 |
| 4:15–4:45 | 左栏「导入角色」→「酒馆卡 JSON」→ 填入示例 → 导入 | 三种导入格式，逐字段校验；酒馆卡里的 `system_prompt` 等字段会被忽略并提示；导入后自动补全设定 |
| 4:45–5:00 | 收尾 | 测试分层、真实评测结果见 EVALUATION.md |

## 备用素材

- 走向 A/B 对比：`docs/eval/direction/` 下同一段历史的三个分支（无走向 / 文档示例走向 ×2），对照表见 EVALUATION §3。
- 注入测试：`docs/eval/injection.md`，或在演示里切到「顾青」。角色卡和走向里的“忽略指令”文字没有被执行，第 2 段的「本段走向」里写明了原因。
- 失败演示：在 fixture 模式下，把走向设为 `[fixture:unavailable] 测试`，可以看到失败原因、尝试次数和「重试」按钮。

## 录屏步骤（如需自己录）

1. macOS 按 `Cmd+Shift+5` → 选择「录制所选部分」→ 框选浏览器窗口。
2. 按上表操作一遍（生成章节的等待可以在剪辑时剪掉）。
3. 也可以直接看自动录制的视频：`npx playwright test --project fullstack` 运行后，视频在 `test-results/playwright/*/video.webm`，报告在 `npx playwright show-report`。
